CSPSP CLIENT CONFIGURATION GUIDE
================================

FILE FORMAT
-----------
Most files use one setting per line: key = value
Lines beginning with # are comments. Keep key names unchanged. Numeric values
outside their supported range are clamped; missing settings use built-in
defaults. Restart CSPSP after manually editing these files: client data and
resources are loaded during startup, not continuously while the game runs.

HUD TIMER OPTIONS
-----------------
  show_round_timer = on/off   Show the timer in non-Horde modes.
  show_horde_timer = on/off   Show total time survived across the Horde run;
                              defaults to off and resets after a squad wipe.

WHICH FILE IS WRITTEN BY THE MENUS?
-----------------------------------
data/config.txt stores user choices made in the Options and local mode setup
screens. Each screen updates only the keys it owns and preserves other keys
and comments. For example, choosing Infection Respawn = In-Place writes:
  respawn = inplace

This does NOT modify modes.txt or any other data file. For settings available
in both files, config.txt has priority and modes.txt is only the fallback when
that key is missing from config.txt. Delete the relevant key from config.txt to
use the modes.txt default again.

OFFLINE GAMEPLAY DATA
---------------------
  player.txt     Team health/armor, pickups, money, movement and hit slowdown
  grenades.txt   Grenade fuse, flash and HE behavior
  modes.txt      Fallbacks for local mode options. Horde supports regroup,
                 wave delay, wave reward, survivor revival, and per-wave
                 health, melee-damage and movement-speed multipliers.
  bots.txt       Offline bot perception, movement and firing behavior

CLIENT PRESENTATION DATA
------------------------
These can affect how both offline and online games look or sound, but they do
not override server-owned gameplay results.
  camera.txt     Camera following, scope ranges and local input response
  hud.txt        HUD positions, radar scale, crosshair size and event timing
  aimmarkers.txt Aim-guide and hitmarker colors, radii, lengths and widths
  effects.txt    Particles, decals and visual performance limits

ONLINE NETWORKING
-----------------
  network.txt    Client network tolerance settings. online_inactivity_timeout_ms
                 controls established-session silence before disconnecting,
                 range 10000-120000 milliseconds. Use the server's value.
  audio.txt      Sound paths, volume and positional sound falloff
  theme.txt      Team, crosshair and radar-marker colors
  resources.txt  Texture paths, including gfx/radar.png
  limits.txt     HUD event queue capacities
  tracers.txt    Per-weapon client-only tracer styles
  lasers.txt     Per-weapon client-only aiming lasers

TRACER CUSTOMIZATION
--------------------
tracers.txt uses one optional record per weapon ID:
  id style red green blue alpha length width

Weapon IDs range from 0-127, RGBA channels from 0-255, length from 0-5000,
and width from 0.1-20. A length of 0 uses the original speed-scaled trail.
Styles are client-only and never change server collision or damage. Visual
chain, ricochet, penetrator and charge styles do not add those gameplay
mechanics. See tracers.txt for the complete style list and descriptions.

LASER CUSTOMIZATION
-------------------
lasers.txt uses optional records keyed by weapon ID:
  id enabled falloffEnabled red green blue alpha width range falloff endDot endDotScale offsetX offsetY

Boolean fields use 0 or 1. Falloff disabled, or a falloff value of 0, produces
a solid beam. The optional endpoint dot shares the beam color and has its own
scale. offsetX moves the emitter forward/back along the aim direction and
offsetY moves it sideways. Old 12-field records without offsets remain valid
and default to 12,0. Missing IDs have no laser. Gun Editor.jar provides a
Laser tab with a live preview for all fields.

PLAYER AND TEAM DATA
--------------------
players.txt controls both team display names and selectable player skins. It
uses row-based entries:
  team <team ID> <display name>
  player <skin ID> <team ID> <atlas cell> <member name>

Team IDs are 0 for T and 1 for CT. Skin IDs are stable network values from 0
through 31 and may be sparse or listed in any order. Each atlas page contains
eight 32-pixel columns shared by its live and dead textures. The team ID controls
which team owns a skin independently of its atlas position. Cells 0..7 use
players/players_dead, 8..15 use players_page_2/players_dead_page_2, and the same
pattern continues through page 4. A row creates a menu slot only when its ID,
team, name, and atlas cell are valid; duplicate IDs and cells outside either
texture are skipped.
Long team lists scroll automatically. If a team has no valid rows, its four
original definitions are restored when the original atlas cells are available.

To add genuinely different skins, create matching 256x64 live/dead atlas pages,
configure their paths in resources.txt, and append player rows using that page's
cell range. Up to 32 total IDs can be configured, with at most 16 assigned to
either team; no empty placeholder slots are created. Run generate_players2.ps1
from the project directory to reproduce the included page-2 original variants.

The resources.txt ammo_ground path selects the 32x32 image used for both map
ammo pickups and the Ammo entry in the buy menu.

OTHER FILES
-----------
  guns.txt       Weapon definitions; it uses its own row-based format
  players.txt    Team names and player skin definitions
  animations.txt Animation definitions; it uses its own row-based format
  favorites.txt  Saved server favorites

WEAPON MUZZLE FLASHES
---------------------
Weapon rows in guns.txt may add an optional muzzle-flash ID immediately before
the weapon name. Existing 18-field rows omit it and use style 0:
  ... buyCategory buyTeams [muzzleFlashId] name

Accepted values are integers from 0 through 127. Style 0 uses the muzzle_flash
resource key. Style N uses muzzle_flash_N, so adding a future style only
requires that entry in resources.txt, its image, and the ID before a weapon name in guns.txt.
Missing resource keys safely use style 0. Each image must be a 128x32 sheet.
The first three 32x32 cells contain randomized frames and the fourth cell is
transparent/reserved, matching the original muzzleflash.png layout. Online
servers send this setting to clients, so client and server binaries must use
the same network version.

ONLINE AUTHORITY
----------------
The dedicated server controls online health, armor, damage, pickups, money,
movement, respawn rules and server bots. Client gameplay values cannot override
it. Server owners edit CSPSPServer/data/gameplay_config.txt and restart the
server. The client then receives authoritative results through network packets.
